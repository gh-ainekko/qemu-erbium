# SmallVM: compact objects and bare-metal Erbium checkpoints

Implemented scope: assessment steps **#1 (LP64-safe C VM)** and **#2 (single-hart
Erbium firmware)**. This is an emulator-validated development port, not a
qualified hardware release or a complete MicroBlocks board package.

## Reproduce

From this repository's root (Ubuntu 24.04 development environment):

```sh
# Host checks need git, make, a native C compiler, Python 3, and coreutils.
scripts/fetch-smallvm.sh
scripts/test-smallvm.sh --host-only

# Cross-build also needs these tools. Do not install an Arduino SDK.
sudo apt-get install gcc-riscv64-unknown-elf binutils-riscv64-unknown-elf curl binutils zstd
scripts/build-smallvm.sh firmware selftest

# Full suite requires this repository's built erbium_emu.
# scripts/build-all.sh sysemu    # if not already built; see root README for dependencies
scripts/test-smallvm.sh

# Optional existing-32-bit-representation regression:
sudo apt-get install --no-install-recommends libc6-dev-i386 lib32gcc-13-dev qemu-user
scripts/test-smallvm.sh --with-legacy32
```

The `--no-install-recommends` is intentional: do not replace/remove the existing
cross compiler packages by installing the generic gcc-multilib metapackage.
This VM's host kernel does not execute IA32 binaries directly; the legacy test
uses `qemu-i386` and UBSan, not a hypothetical RV32 mode on Erbium.

The first cross-build downloads a SHA-256-pinned Ubuntu picolibc 1.8.6-2 package
(about 158 MB). It extracts only RV64IM/LP64 libc, headers and notices into
`build/smallvm/deps`; no system libc installation or custom libc is required.
Host-only testing does not need picolibc or the RISC-V toolchain.

Overrides:

- `SMALLVM_SRC=/absolute/path` selects a source checkout for fetch/build/test.
- `SMALLVM_BUILD=/absolute/path` selects test output; direct make uses `BUILD=...`.
- `ERBIUM_EMU=/absolute/path/erbium_emu` selects the emulator for the full suite.
- `make -C smallvm CROSS=...` selects a matching bare-metal GCC toolchain.
- `make -C smallvm ERBIUM_TIMER_HZ=...` selects the timer conversion; the current
  emulator's configured timer is **2 MHz**. The selftest deliberately rejects
  a 10 MHz conversion with the same emulator configuration.

Fetch refuses dirty/unverified/differently patched existing directories. Preserve
such a tree and choose a new `SMALLVM_SRC`; it never resets or deletes your work.
When deliberately editing the port, use `make -C smallvm ...` directly, then
export/revalidate patches before using the locked end-to-end test script.

Run individual checkpoints without rebuilding everything:

```sh
make -C smallvm host-selftest
make -C smallvm host-selftest-sanitize
make -C smallvm host-selftest-32
python3 smallvm/tests/check_elf.py build/smallvm/smallvm.elf
python3 smallvm/tests/run_emulator.py build/smallvm/smallvm-selftest.elf --output build/smallvm/manual-test
python3 smallvm/tests/run_emulator.py build/smallvm/smallvm.elf --mode protocol --output build/smallvm/manual-protocol
```

The runner supplies a raw PTY, separates UART bytes from emulator diagnostics,
derives reset PC from the ELF, enforces a timeout and terminates the otherwise
infinite firmware loop after success. A max-cycle simulator exit is not used
as a proxy for firmware success.

## #1: Representation and ownership

Base: Codeberg `MicroBlocks/smallvm` commit
`49f337529294640def7b27a2ee1c4e7ba88ccdbb`; three patches produce source tree
corresponding to development commit `b3e0be9` (git-am commit IDs can differ).
A fresh upstream fetch/reapplication was compared by Git tree hash, not merely
by file names. Fetch records the patch digest and resulting tree.

- `SMALLVM_COMPACT_32=1` uses `uint32_t OBJ`. Object headers/fields, downloaded
  bytecode/literals, and persistent record widths remain unchanged.
- `ptrToObj` rejects high, unaligned and reserved object addresses; `objToPtr`
  decodes through `uintptr_t`. Heap/code/static object storage must be below
  4 GiB. On this target all of it is in low MRAM.
- Native stacks, instruction/record pointers and primitive function pointers
  remain native-width. The LP64 host test actually calls a shared-library
  primitive above 4 GiB through the VM's named-call opcode.
- Existing 32-bit builds retain pointer-shaped OBJ unless compact mode is
  explicitly requested. The same patched C core is executed in legacy mode
  in the 32-bit regression; this is not a full Arduino board/peripheral build.
- Allocation fills, byte-source interior pointers, roots, resize and cyclic GC
  are tested with collection forced *inside* allocating operations, not just
  after them. Native locals are not magically GC roots.
- Exported `pushLiteral` strings/byte arrays become heap-owned copies. This
  prevents globals/lists/task stacks from retaining stale addresses when the
  RAM code store compacts. The tradeoff is additional allocation/GC work;
  literal interning/performance optimization is future work. Lookup-only
  primitive names remain temporary code references.
- Task code pointers are repaired using the current function's chunk index;
  return addresses/IPs remain offsets. Arbitrarily replacing a running chunk
  is still outside the update contract.

The port also fixes concrete bugs exposed by these tests: pointer-reversal
marking of self-cycles, stale string slices across moving GC, unchecked
primitive-name components, ILP32/LP64 numeric conversion divergence, and
rounded persistent-record reads beyond the caller's payload.

This is a **low-address compact VM**, not a general 64-bit object heap. Normal
PIE executables and arbitrary host malloc/stack storage cannot hold VM objects.

## #2: Bare-metal platform

The firmware uses GCC `rv64imc_zicsr_zifencei`, LP64 soft-float ABI, and matching
RV64IM libc/libgcc. ELF checks reject hard-float ABI, A/F/D/vector extensions,
unrecognized instructions, dynamic loading, out-of-MRAM segments, and RWX loads.
No Go runtime, Arduino framework, OS threads, or libm is linked.

Startup initializes gp/tp/sp, minion-specific CSRs, mtvec and BSS, and parks
nonzero hart IDs before they can touch VM state. Data/TLS data are initialized
by ELF loading; BSS/TLS BSS are cleared by firmware. Fatal traps record
cause/PC/mtval/original SP in `smallvm_fault_state`, switch to a separate fault
stack, and stop. Only the selftest image prints raw fault diagnostics.

Memory layout (defaults):

- Link text at `0x40010000`; reserve the first 64 KiB of MRAM for future use.
- Four-byte-cell VM heap: 64,000 bytes, well below the current packed-size limit.
- Upstream RAM code store: 40 KiB, **volatile** across firmware boots.
- C stack: 32 KiB; fault stack: 4 KiB. No general-purpose malloc arena.
- Normal image currently occupies roughly 209 KiB including BSS and stack
  reservations; inspect the map/headers for exact load sizes.

UART uses 32-bit MMIO accesses on the Shakti register strides. RX is
nonblocking/bounded; TX reports partial progress. The normal build emits only
MicroBlocks-framed bytes, including a framed readiness notice. Peripheral
operations are unsupported or intentionally absent (zero pin counts, false
buttons, harmless output-off hooks). UART divisor/framing are provisional:
stream emulation does not qualify physical baud.

The timer conversion is independently checked against the minion CYCLES
performance counter. In this emulator, the 200 MHz cycle source is divided by
5 before the explicitly programmed /20 prescaler: 2 MHz MTIME. Standard
`rdcycle` is not a useful reference in the present simulator. Neither historical
TamaGo's 50-us conversion nor the TRM's 10-MHz profile is assumed to apply here.
Physical clock/baud/reset qualification remains separate.

## Verified checkpoint results (2026-10-07)

The common suite passes **772 checks total**, including **385 forced-GC/name/
literal regressions**, on native LP64, ASan+UBSan LP64, legacy32+UBSan under
qemu-i386, and the actual RV64 emulator. Additional tests:

- Real named primitive pointer above 4 GiB; zero-argument and two-argument calls.
- High and unaligned object-address rejection (bounded subprocesses).
- Fresh upstream patch application and four fetch/no-overwrite tests.
- Single-minion and all-eight-minion startup with `0xa5`-prefilled MRAM.
- Initialized data/TLS and zeroed BSS/TLS BSS sentinels.
- Negative BSS control: replace the startup clear store with NOP, prefill MRAM,
  and require the startup test to reject it. The loader is not hiding missing
  firmware BSS initialization.
- Timer/cycle ratio and approximately 200,000 cycles for a 1-ms delay; a wrongly
  configured 10-MHz conversion is rejected.
- Injected illegal instruction: require cause 2 and exact injected PC plus
  valid recorded stack address. The mutated ELF is stored under results/fault.
- Clean normal-firmware UART ping/version (`v416 Erbium`). This is a transport
  smoke test, not a claim of complete IDE interoperability or large-upload
  reliability.

`results/no-bss` and `results/bad-timer` deliberately contain failing firmware
messages: the enclosing tests pass only if those bad images are rejected.
Sanitizer findings are fatal; none are suppressed by a sanitizer ignore list.

## Deliberately not included

Durable MRAM code storage, xSPI-host installation/boot, firmware installers,
full desktop/browser IDE integration, reliable bulk UART transport fixes,
board GPIO/I2C/SPI/sensors, graphics, Wi-Fi/BLE, SMP, accelerator primitives,
and physical hardware validation. Later native drivers must obey the moving
GC/root ownership rules and must not retain raw code-store literal handles.
Bytecode remains trusted compiler output, not a hardened untrusted-code sandbox.

Upstream changes retain SmallVM's MPL-2.0 file notices. New platform/build/test
files are Apache-2.0. Picolibc and GCC runtime notices are included by the review
packager; the libc package's full copyright file is cached beside the selected

archive. No emulator binary or poisoned 16-MiB image is included in that archive.
